# Decision log

Short records of decisions and why. Add new entries at the bottom.
Do not reverse a decision without discussing it first.

| ID | Decision | Rationale | Alternatives considered |
|---|---|---|---|
| D-001 | One repo, two independently versioned components | One product, one developer, a shared API contract that changes on both sides at once | Separate repos (adds cross-repo version coordination) |
| D-002 | Slides arrive via a local acquisition folder on the device; no upload | Mirrors a real instrument, where capture and analysis happen on the same device; avoids streaming multi-GB files through two hops | Browser upload through Node (moved to future work) |
| D-003 | The browser never calls the inference service; Node mediates | Device exposes a narrow, versioned API; UI layer can't reach the instrument directly | Browser calls Python directly (simpler, but weaker boundary) |
| D-004 | Python owns job state in SQLite; unfinished jobs become `INTERRUPTED` on restart | Single source of truth on the device; no silent resumption of partial work | In-memory state; Node-side state |
| D-005 | One GPU worker, FIFO queue | One RTX 3090; predictable memory use and timing | Concurrent jobs |
| D-006 | Poll the acquisition folder every 2 s; register only after file size is stable | Files appear before copying finishes; file-change notifications are unreliable across the WSL2/Windows boundary | inotify / watchdog library |
| D-007 | Acquisition folder lives inside the WSL2 filesystem | Reading slides across `/mnt/c` is slow and file events are unreliable; Windows can still copy in via `\\wsl$\` | Folder on the Windows drive |
| D-008 | Slide IDs are UUIDs; SHA-256 stored for feature-cache keys | IDs never derive from filenames; re-analysing an identical file reuses cached features | Filename-based IDs; hash as primary key |
| D-009 | Minimal PHI controls: no associated images, allowlisted metadata, no filenames in API/logs/UI | Real WSI files can carry patient identifiers in label images and metadata; cheap to prevent exposure | Full de-identification of files (future work); skipping PHI entirely |
| D-010 | Heatmap is a server-rendered PNG of percentile-normalized attention | Simple and robust; raw softmax attention is tiny and skewed and would look uniform | Per-patch JSON drawn in the browser (future work) |
| D-011 | Quality metrics for v0.1: tissue area (mm², or fraction if no mpp), usable patch count, uncertainty flag (probability in [0.3, 0.7]) | All are byproducts of steps that already run; uncertainty flag is a risk control | Blur fraction (stretch); artifact detection |
| D-012 | Fixed error codes, plain UI errors, no automatic retries | Failures are visible and explainable; each code can be triggered on purpose | Retry logic |
| D-013 | Progress via SSE (Python to Node to browser); slide list via polling | SSE fits one-way progress; polling is simplest for an infrequently changing list | WebSockets; polling for progress |
| D-014 | Plain JavaScript, Express, ES modules, no bundler or framework | Matches the target team's stack; keeps the client inspectable | TypeScript; React; Vite |
| D-015 | Python environment via `uv` with a lockfile; no Docker in v0.1 | Simple; lockfile gives exact versions for SOUP | conda; Docker (future work) |
| D-016 | Prefer standard library and built-ins over new dependencies | Smaller SOUP surface | ORMs, HTTP client libraries |
| D-017 | Mac and desktop connect over Tailscale; shared `X-Device-Token` header | Private network, works off home Wi-Fi, nothing exposed publicly | SSH tunnel; LAN only |
| D-018 | Pretrained WSInfer-MIL CAMELYON16 metastasis model; demo on CAMELYON16 test-split slides | Ready-to-run open MIL model on gigapixel slides; test split is held out if the model trained only on the training split (verify in spike) | MIL-Lab FEATHER (no classifier head, gated, non-commercial) |
| D-019 | Git: Conventional Commits, feature branches, squash merge, per-component tags | Clean, reviewable history; shows disciplined process | Merge commits; single version |
| D-020 | MIT license for this repository's code | Simple and permissive; compatible with Apache-2.0 dependencies when their notices are kept | Apache-2.0 |
| D-021 | Inference service pinned to Python 3.12 (`.python-version`, `requires-python`) | Broadest wheel support across PyTorch, OpenSlide, and the MIL stack on both macOS and WSL2; uv provisions it on either machine | 3.13 (newer, some ML wheels lag) |
| D-022 | Inference config comes from environment variables, read with `os.environ` into a frozen dataclass; `.env` is loaded by `uv run --env-file` | No extra dependency; config fails fast at startup (missing or short token) | python-dotenv; pydantic-settings |
| D-023 | Token check is deny-by-default pure ASGI middleware with constant-time comparison; only `/v1/health` is public; Swagger UI and ReDoc disabled | New routes are protected without opt-in; unknown paths return 401, not 404; pure ASGI does not wrap streaming (SSE) responses; docs pages can't send the header and load CDN scripts | Per-router FastAPI dependency (easy to forget on a new router); `BaseHTTPMiddleware` |
| D-024 | HTTP-level error codes (`UNAUTHORIZED`, `NOT_FOUND`, `VALIDATION_ERROR`, ...) alongside the pipeline codes; 500 responses and logs never include exception text | Every error keeps the contract shape; exception text can contain file paths (REQ-006) | FastAPI default `{"detail": ...}` |
| D-025 | OpenSlide C library comes from the `openslide-bin` wheel, not brew/apt | Same pinned library version on the Mac and WSL2, recorded in `uv.lock` for SOUP; `uv sync` is the only setup step | System package via Homebrew / apt |
| D-026 | Registry scans only the top level of the acquisition folder, skips hidden files, and accepts single-file formats `.tif .tiff .svs .ndpi .scn .bif` | Temporary and partial copies are ignored; the size-stability check can't cover multi-file formats such as `.mrxs` | Recursive scan; trying every file with OpenSlide |
| D-027 | Each SQLite operation opens its own short-lived connection; database in WAL mode | The poller thread and request threads never share a connection; readers aren't blocked by the poller's writes | One shared connection with a lock; an ORM |
| D-028 | Unreadable slides store a fixed error message; logs carry exception types only, including uvicorn's unhandled-exception log (filter on `uvicorn.error`) | OpenSlide's exception text contains the file path (REQ-006) | Logging and storing exception text |
| D-029 | A file that disappears from the acquisition folder keeps its slide row unchanged in v0.1 | No contract change; a missing file fails cleanly at tile or job time | Delete the row (conflicts with job foreign keys); mark unreadable |
| D-030 | Deep Zoom tiles: 254 px with 1 px overlap, JPEG quality 75, `limit_bounds=False` | 256 px tiles are the OpenSlide/OpenSeadragon convention; untrimmed bounds keep the Deep Zoom image equal to level 0, so the level-0 heatmap overlays with no offset | `limit_bounds=True` (offsets for slides with bounds properties); PNG tiles (larger) |
| D-031 | Open slides are kept in a 4-entry LRU cache shared by request threads; eviction drops the entry without closing it | OpenSeadragon fires many parallel tile requests and reopening per tile re-parses headers; OpenSlide reads are thread-safe; closing on eviction could break an in-flight read, and the handle closes itself when garbage-collected | Open per request; configurable cache size; close on eviction with reference counting |
| D-032 | New HTTP-level code `SLIDE_NOT_READY` (409) for any request that needs a `ready` slide; raised via `ApiError`, which carries its own status and code | One code for arriving, registering, and unreadable; the slide object already says why; reused by `POST /v1/jobs` | Split codes per status; generic `CONFLICT`; 404 for non-ready slides |
| D-033 | At most one queued or running job per slide; a second `POST /v1/jobs` gets `409 JOB_ALREADY_ACTIVE`. Enforced by a partial unique index on `jobs(slide_id) WHERE status IN ('queued','running')` | A double-click can't queue two GPU runs of the same slide; the database enforces the rule atomically, so two simultaneous requests can't both pass a check-then-insert | Allow duplicates (UI-only guard); check in Python under a lock |
| D-034 | SSE streams poll a versioned in-memory job state every 250 ms; SQLite progress is written on stage changes and at most once per second; the final row is written before the in-memory state is dropped | No cross-thread asyncio plumbing; fast updates merge into one event; a slow client can't grow a backlog; disk writes stay bounded. The write-then-drop order means "no state" always implies "row is final" | Per-client asyncio queues fed with `call_soon_threadsafe`; writing every update to SQLite |
| D-035 | SSE via FastAPI's built-in `EventSourceResponse` (it sends `: ping` keep-alives every 15 s) | Already in the pinned FastAPI, so no new SOUP | `sse-starlette`; a hand-formatted `StreamingResponse` |
| D-036 | The pipeline is a callable `(slide_row, report) -> PipelineResult`; it fails with a defined code by raising `PipelineError`, and any other exception becomes `INFERENCE_FAILED`. Until item 6 a stub runs, and its completed jobs have `result: null` | The worker doesn't depend on the model code, and tests inject fake pipelines; the stub returns no fake probability, because one could be mistaken for a real result | Pipeline as a class hierarchy; stub returning made-up probabilities |
| D-037 | The service is run with `--timeout-graceful-shutdown 5`. On shutdown, the running job stops at its next `report()` and is marked `INTERRUPTED`; jobs still queued are marked by the next startup sweep | Uvicorn waits for open streaming responses before it runs lifespan shutdown, so an open SSE stream held Ctrl+C until the job finished (seen in manual testing). One startup sweep covers crashes and clean stops alike | No timeout (shutdown waits for every job); sweeping queued jobs at shutdown too |
| D-038 | The pipeline stages (segment, patch, extract features, aggregate) are written in this repo on OpenSlide and PyTorch; wsinfer-mil is not a runtime dependency. The models themselves are unchanged (D-040) | wsinfer-mil 0.1.0 is runner glue around the models: it needs `zarr<3`/`tifffile<2025.5` pins to import, reads slides with tiffslide (a second reader), keys its cache by file name (conflicts with D-009) and leaves the MIL model in training mode. The spike showed identical patches and features with OpenSlide | Depend on wsinfer-mil and call its stage functions; call its CLI |
| D-039 | Tissue segmentation follows wsinfer-mil's method (2048 px thumbnail, HSV saturation, median blur 7, closing 6 px, drop objects < 200² µm², fill holes < 190² µm²) with a fixed threshold of **20** instead of 7, implemented with OpenCV only. Patches lie on a global 128 µm grid from the slide origin; a patch is kept when the mask pixel at its centre is tissue | At 7 the tinted Philips background (saturation about 8) counts as tissue (96–100% of two staged slides). At 20 all cellular tissue is kept. Per-slide Otsu (about 60) was tried and rejected: the tissue it drops is real (lymphocytes between fat cells, stroma). OpenCV-only and a centre-pixel test keep the SOUP to one library and are easy to explain; a test checks the patch count against the spike. Known limitation: pale fat (saturation 7–20) is lost, and the value is tuned to these scans | Threshold 7 (wsinfer-mil default); per-slide Otsu; threshold relative to each slide's background (future work); exact port with scikit-image and shapely (bit-identical patches, two more dependencies) |
| D-040 | Both models are loaded from their TorchScript files (`torch.jit.load`) once at startup and put in `.eval()` mode. Pinned revisions: MIL `kaczmarj/breast-lymph-nodes-metastasis.camelyon16@507b473a`, encoder `kaczmarj/CTransPath@d426c122`. The reported model `version` is the short Hugging Face revision | The MIL file is saved in training mode, so without `.eval()` dropout makes every run differ (spike: 0.164–0.167 on identical input). CTransPath is only published as TorchScript. These repos have no version numbers; the revision identifies the exact files. `torch.jit` is deprecated but works in the pinned PyTorch | Load the MIL `model.safetensors` into a re-implemented ABMIL (fallback if TorchScript is removed); ONNX Runtime (another dependency) |
| D-041 | Weights are fetched once by a standard-library script from the pinned revision URLs into `services/inference/models/weights/` (gitignored) and checked against SHA-256 values in `models/manifest.json` (repo, revision, file, SHA-256, licence). Nothing touches the network at runtime | Reproducible, scriptable setup with no `huggingface_hub` dependency; the manifest is the single place that names the exact model files (REQ-016) | `huggingface_hub` downloads into its cache; manual download steps in the README |
| D-042 | Model weights are used as downloaded and never redistributed. MIL model: CC-BY-4.0, credited in the README. CTransPath weights: GPL-3.0 per the Hugging Face card, recorded in `docs/soup.md` | Running the weights does not combine them with our MIT code into a distributed work; attribution satisfies CC-BY. The CTransPath licence is still to be verified against the original release | Committing weights; choosing a different encoder |
| D-043 | A job fails with `NO_TISSUE` when segmentation yields fewer than 16 patches | Zero is too strict: a few patches of debris on a blank slide would otherwise produce a confident-looking result | Fail only at 0 patches; a minimum tissue area |
| D-044 | A slide without microns per pixel fails its job with a new job error code `NO_RESOLUTION`; REQ-013 no longer has a no-mpp branch (replaces the "or fraction if no mpp" part of D-011) | The model needs 128 µm patches; without mpp the patch size is unknown and any result would be invalid. A dedicated code tells the user why | `INFERENCE_FAILED` with a message; assume a default mpp |
| D-045 | Feature extraction uses a PyTorch `DataLoader` with a `FEATURE_WORKERS` setting (default 8) using the `forkserver` start method, `pin_memory=False`, batch 64, fp32. `FEATURE_WORKERS=0` (in-thread loading) is the fallback. Worker start-up cost is measured in item 6 | Spike: 82 patches/s with 0 workers, 486/s with 8. `fork` from a multi-threaded process holding a CUDA context is fragile; `forkserver` starts workers from a clean process. Pinned host memory failed intermittently under WSL2 | `fork` (default); always 0 workers; a thread pool |
| D-046 | Feature cache key: slide SHA-256 + encoder SHA-256 + patch settings (patch size in µm, tissue threshold). Coordinates and features are stored as `.npy` under `DATA_DIR/cache/`; no eviction in v0.1. Segmentation always runs (0.1 s); on a cache hit the patch-count progress jumps straight to total/total | Coordinates depend on the threshold and patch size, so they belong in the key (refines D-008). `.npy` needs no extra library. The mask is needed for quality metrics anyway | HDF5 (h5py); caching the mask too; keying on SHA-256 only |
| D-047 | Item 6 fills `probabilities` and `predicted_class`, and saves attention scores and patch coordinates to `DATA_DIR/jobs/<job_id>/` for the heatmap. `uncertain` and `quality` stay `null` until item 7 | Keeps each roadmap item scoped; item 7 renders the heatmap and computes metrics from saved outputs without re-running the model | Compute everything in item 6 |
| D-048 | The real pipeline runs only on the desktop GPU. On macOS, PyTorch installs the CPU build through platform markers in `pyproject.toml`, so tests run there with fake pipelines. The service refuses to start on any machine where the model files are missing or fail their hash check (REQ-016) | CUDA wheels don't exist for macOS. The Mac reaches the device over Tailscale and doesn't need to run models. One startup rule everywhere, no "no-models" mode to test | CPU/MPS inference on the Mac; starting without models and failing jobs |
| D-049 | Models are verified and loaded in `create_app()` through an injectable `model_loader`, not in the lifespan. The stub pipeline is removed; tests use small fake models (`tests/fakes.py`) | The job queue is built with its pipeline in `create_app()`, and tests swap `app.state.job_queue` before the lifespan runs. `uvicorn --factory` calls `create_app()` at startup, so a missing or mismatched weight file still stops the service (REQ-016). The stub was only used by its own test once the real pipeline existed | Load in lifespan and attach the pipeline to the queue afterwards; keep the stub as a dev mode (conflicts with D-048) |
| D-050 | The pipeline is called as `pipeline(slide, report, *, job_id)` (extends D-036). Each completed job saves `coords.npy`, `attention.npy` and `mask.npy` to `DATA_DIR/jobs/<job_id>/` | The job ID names the output folder. Item 7 needs the tissue mask for tissue area and fraction as well as attention and coordinates for the heatmap (D-047); saving it (a few MB at most) avoids re-reading the slide | Pass an output folder instead of the ID; re-segment in item 7 |
| D-051 | OpenCV-only segmentation reproduces wsinfer-mil's scikit-image steps exactly: the 6 x 6 closing uses explicit dilate/erode anchors, and small objects and holes use 4-connectivity. The encoder transform is Pillow bilinear resize to 224 px plus torch normalisation, with no torchvision. The feature cache trusts the slide SHA-256 from registration and writes entries atomically (temporary folder, then rename) | Checked against wsinfer-mil in the spike environment: masks bit-identical on all four staged slides (`cv.morphologyEx` alone shifted about 11,000 mask pixels on test_062), transform output bit-identical on 200 test_062 patches including edge patches. The centre-pixel patch test (D-039) keeps 1.7-4.4% more patches than wsinfer-mil's polygon test, all on the tissue outline (test_062: 2,281 vs 2,226; P(metastasis) 0.131 vs 0.135). Re-hashing a 1 GB slide per job would cost seconds for a file D-029 treats as unchanged | `cv.morphologyEx` closing; torchvision; re-hashing the slide per job |
| D-052 | Feature-extraction workers ignore SIGINT (`worker_init_fn`), and the forkserver preloads `app.pipeline.features` | A terminal Ctrl+C reaches the workers too; they exited, and the running job failed `INFERENCE_FAILED` instead of stopping as `INTERRUPTED` at its next report (D-037). Seen in manual testing. Preloading imports torch once in the forkserver instead of once per worker: worker start-up fell from about 3.1 s per job to about 1 s (2.4 s for the first job after startup), and test_062 extraction from 7.7 s to 5.4 s | Treat any failure after shutdown starts as `INTERRUPTED`; persistent workers across jobs |
